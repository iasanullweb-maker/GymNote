# GymNote 인수인계

현재 디렉터리에서 GymNote 루트·적용 지침, 요청 문서·소유 범위를 확인한다. HANDOFF와 병행 작업 GUIDE·ASSIGNMENTS·workspaces.json을 읽어 현재 운영과 과거 이력을 구분한다. 공통 문서 편집은 담당 소유 범위 또는 사용자 직접 요청을 따른다. 다른 역할이면 본인 보고서에 남기고 다른 채팅으로 자동 전송하지 않는다.

## 사실 수집

- 본인과 원본 폴더의 git status --short --branch, 최종 커밋, 통합 대상·ancestry를 확인한다. source·integration·검증·배포 SHA가 다르면 역할을 구분한다. 미추적 파일·다른 소유자 변경은 포함하지 않는다.
- 검사는 명령·환경·대상 SHA·통과/실패/건너뜀/미실행과 이유를 모은다. XCTest·Release 빌드·웹 모사·실기기를 구분한다. 새 코드의 근거로 과거 버전 성공을 쓰지 않는다.
- 배포·서버 상태는 이번 확인과 기존 기록을 구분한다. 직접 확인하지 않은 run/버전/운영 적용을 확인한 것처럼 새로 쓰지 않는다. 원격 상태가 필요한 요청은 읽기 전용 도구로 확인하고 정보가 없으면 미확인으로 남긴다.

## 문서 편집

새 기록은 최신 관련 위치에 짧게 추가하고 사용자 시간대 날짜를 사용한다. 기존 다른 작업 문단·과거 이력을 보존한다. 완료 항목 반복보다 다음 작업자가 바로 진행할 현재 상태·행동·전제를 남긴다. 완료 체크는 실제 근거에 맞게 변경한다.

필요한 항목만 포함한다.

- 변경과 관찰 가능한 결과, 담당 파일/소유 범위.
- 검증·미실행, 전체 iOS 빌드 여부.
- 코드 커밋·로컬 통합·원격 push/배포/운영 적용 상태.
- 남은 실기기/두 계정 검사, 환경·권한·의존성, 다음에 적용할 GymNote 스킬.

개인 계정·친구 코드·토큰·원본 로그는 문서/Git에 넣지 않는다. 익명화한 재현·필요한 증거 링크만 남긴다. 불명확한 완료는 확인 과제로 표시하며 진행 중·차단을 완료로 바꾸지 않는다.

## 문서도 커밋과 통합

diff·링크·현재 사실을 검토하고 git diff --check를 수행한다. 본인 파일만 명시적으로 커밋한다. 워크트리면 gymnote-task의 통합 절차 또는 기존 역할 스크립트로 공통 잠금 아래 기존 브랜치에 통합한다. 원본 폴더 직접 수정도 커밋까지 완료한다.

최종 보고 직전에 양쪽 상태·커밋·ancestry를 재확인한다. 최종 커밋 ID는 완료 응답에서 제공하므로 문서에 자기 해시를 넣으려고 반복 커밋하지 않는다. 통합 예정과 최종 결과를 구분한다. 통합이 막히면 편집·검증·커밋 중 끝난 단계와 남은 통합·원인을 보고한다. 원격 push·배포는 문서 마무리에 자동 포함되지 않는다.
