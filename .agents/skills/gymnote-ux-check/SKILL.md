# GymNote UX 확인

현재 디렉터리에서 GymNote 루트를 확인하고 적용 지침·요청의 검증 환경을 읽는다. 아래 모드 중 요청에 맞는 것만 수행한다. 기기·도구가 없으면 가능한 검사를 진행하고 의도한 검증 중 미실행 부분을 남긴다. 웹 검증으로 실제 iOS 검증을 대체하지 않는다.

## 과제와 근거

- `simulation/scenarios/README.md`, 관련 시나리오 JSON, 필요할 때 `simulation/personas/`를 읽어 변경과 관련된 목표·기대 결과·시작 상태를 선택한다. 기존 시나리오가 범위를 다루지 않으면 담당 소유 범위 안에서 보완하거나 요청 흐름을 별도 기록한다. 매번 모든 시나리오를 실행하지 않는다.
- 대상 앱/프로토타입 커밋, 기기·OS·화면 크기·글자 크기, 초기 데이터, 과제 순서와 관찰된 전후 상태를 기록한다. 결과는 새 run ID의 `simulation/runs/` 아래에 보관한다. 이전 결과를 덮어쓰지 않는다.
- 취소 후 기록 보존, 저장 후 반영, 편집 이동 잠금 해제, 선택 날짜 복귀, 실제 횟수와 계획 값 구분 등 관련 회귀를 확인한다. 화면만으로 저장·동기화·권한 성공을 추정하지 않는다.

## 웹 행동 프로토타입

`simulation/web/README.md`를 읽는다. Node 24 이상으로 관련 `tests.mjs`, `test-ui.mjs`를 실행하고 새 run ID로 `build.mjs preview <run-id>`를 생성한다. 조작이 필요하면 허용된 브라우저 도구로 연다. HTTP가 필요하면 `serve.mjs <run-id>`의 루프백 서버를 사용하고 종료 시 본인 서버를 중지한다. 생성 HTML 갱신 후에는 서버도 재시작한다.

상태·이벤트 JSON을 내보내고 문제와 재현 과제를 연결한다. `build.mjs batch <run-id>`는 고정 스크립트 60세션 재생 검사이며 AI 사용자 실험·실제 앱 사용성 성공률이 아니다. 웹 수정은 제품 Swift 수정으로 자동 반영되지 않는다.

## 네이티브 캡처·실행기

- 캡처 요청에는 `simulation/capture/README.md`를 읽고 Mac/Xcode의 격리 캡처 테스트와 실제 첨부물 수집 절차를 따른다. 미실행 화면은 pending, 실패 테스트는 failed로 유지한다. 직접 View 렌더는 탭 탐색·저장·알림·친구 권한 성공의 근거가 아니다.
- 입력 점검·실험 계획에는 `simulation/runner/README.md`, `simulation/contracts/README.md`를 읽고 --validate-only 또는 --dry-run을 사용한다. 현재 실행기는 두 모드만 지원한다. dry-run은 not-run/not-evaluated, 모델 사용량 0이며 성공 판정을 만들지 않는다.
- live 모델·앱 조작 어댑터가 준비됐다고 가정하지 않는다. 구현·환경·승인 범위를 확인한다. pass/fail은 해당 검사를 판정할 수 있는 환경에서 수집한 증거가 있을 때만 기록한다.

## 실제 iPad·클라우드

`docs/ux-simulation/REAL_DEVICE.md`, `docs/RELEASE_DEVICE_CHECKLIST.md`의 관련 항목을 읽는다. 미러링은 사용자가 기기를 조작하고 에이전트가 관찰하며 원격 터치나 상시 관찰로 보고하지 않는다. 현재 사용 가능한 도구로 실제 화면 접근이 가능한지 확인한다. 필요한 기기 조작이 불가능하면 사용자에게 최소 과제와 기록할 결과를 안내한다.

클라우드 요청에는 `simulation/cloud/README.md`와 최신 조사 기록을 확인한다. IPA 구조 검사, 업로드/설치, 앱 실행, 과제 수행을 구분한다. 계정·기기·재서명·요금제 조건은 실행 시 확인하고 유료 사용·외부 업로드는 승인 범위를 따른다.

실제 계정 화면·친구 코드·토큰·개인 기록은 Git에 넣지 않는다. 합성 데이터나 지정 테스트 계정을 사용한다. 사용자 진술은 직접 관찰과 구분한다.

## 결과 전달

과제별 환경, 관찰/검사 결과, 증거 경로, 재현 순서, 미실행, 개선안과 재검증 방법을 기록한다. 제품 문제와 모사의 한계·환경 장애를 구분한다. 본인 배정 결과 문서에는 익명화한 내용만 남긴다. 수정 권한이 있으면 제품 수정 후 같은 관련 과제를 재검증하고 본인 문서/코드 변경은 작업 규칙에 따라 커밋·로컬 통합한다.
