# 로컬 통합

저장소 루트 기준 경로다. `AGENTS.md`의 상시 통합 지시와 시작 당시 기존 브랜치를 따른다. main으로 임의 변경하지 않는다. 각 채팅이 본인 작업을 통합하며 병합 구간만 공통 잠금으로 직렬화한다.

## 기존 도구 선택

- `workspaces.json`의 A/B/C/D 경로·브랜치와 일치하는 워크트리만 `scripts/parallel_work.ps1 -Mode Integrate -Role <역할>`을 사용한다. unified 배정과 일치할 때만 `-Unified`를 사용한다. UX 지정 브랜치는 `scripts/ux_simulation_integrate.ps1`의 ValidateSet을 확인한다.
- 일반 작업을 이 제약에 맞추려고 배정표를 수정하지 않는다. 아래 직접 통합 절차를 적용한다.
- 기존 스크립트는 최신 기준 확인·기능 검사·fast-forward를 자동 강제하지 않는다. 스크립트 사용 전에도 아래 준비를 하고 잠금 안의 조건 확인과 fast-forward를 보장해야 한다. 현재 스크립트가 이 조건을 보장할 수 없으면 직접 통합 절차를 사용한다.
- 지정 스크립트는 소스의 미추적 파일도 차단한다. 본인 새 산출물은 검토 후 필요한 파일만 커밋하고 다른 작업의 미추적 파일은 삭제·임의 stage하지 않는다. 이를 피하려고 배정이나 검사 조건을 완화하지 않는다.

## 준비와 검증 — 잠금 밖

1. `git worktree list --porcelain`과 현재 배정으로 원본 폴더·대상 브랜치를 확정한다. 본인 변경만 커밋하고 양쪽 진행 중 Git 작업과 기존 변경을 확인한다.
2. 원본 대상 브랜치의 최신 HEAD를 기준 커밋으로 기록한다. 본인 깨끗한 워크트리에 그 커밋을 병합한다. 이미 포함됐으면 불필요한 병합을 만들지 않는다. 충돌은 본인 워크트리에서 해결·커밋하고 검토한다.
3. 합쳐진 소스에서 변경 영향에 맞는 검사를 수행한다. 소스 SHA·기준 SHA·명령·결과·미실행을 본인 결과 문서에 기록한다. 작은 UI의 전체 검사 유예는 AGENTS의 기술 검증 대기 규칙을 따른다. 문서만 추가됐으면 제품/검사 입력 동일성을 확인하고 문서·공백 검사를 수행한다.
4. 최종 기록도 커밋하고 검증 대상과 최종 소스의 차이를 확인한다. 검사 입력이 달라졌으면 필요한 검사를 다시 실행한다. 긴 검사·CI 대기 중에는 통합 잠금을 보유하지 않는다.

## 병합 — 잠금 안

1. **원본 폴더**의 `.validation-tools/ux-integration.lock`을 FileMode.CreateNew로 원자적으로 획득한다. 잠금에 브랜치·소스 SHA·기준 SHA·PID를 기록한다. 획득 실패 시 소유자 잠금을 삭제하지 않는다.
2. 소스 HEAD 불변, 원본 대상 브랜치, 양쪽 진행 중 merge/rebase/cherry-pick/revert 부재, 양쪽 추적 파일 미커밋 변경 없음, `git diff --check <기준 SHA>..<소스 SHA>`를 확인한다. 원본 미추적 파일은 그대로 보존한다.
3. 대상 HEAD가 기록한 기준 SHA와 다르면 원본을 수정하지 않고 본인 잠금을 해제한다. 최신 기준 반영·영향 검증부터 다시 수행한다. 이전 검사의 재사용은 해당 검사 입력의 동일성 근거를 남기는 경우에만 가능하다.
4. `git merge-base --is-ancestor <기준 SHA> <소스 SHA>` 성공을 확인하고 원본 폴더에서 `git merge --ff-only <소스 SHA>`를 실행한다. 실패하면 우회 병합·reset·강제 push·임의 stash 없이 원인을 확인한다.
5. 대상 HEAD가 소스 SHA와 일치하고 source ancestry·공백 검사가 통과하는지 확인한다. finally에서 **본인이 획득한 잠금만** 닫고 해제한다. 잠금 없이 상태가 바뀐 정황이 있으면 완료 주장을 멈추고 확인한다.

권한 때문에 원본 폴더·Git 공통 디렉터리에 접근할 수 없다면 해당 작업에 필요한 권한으로 실행한다. 실제 거부가 남으면 완료한 단계와 차단 원인을 보고한다. push와 배포는 로컬 통합의 일부가 아니다.
