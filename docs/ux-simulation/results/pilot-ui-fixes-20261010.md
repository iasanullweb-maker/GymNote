# 파일럿 후속 UI 수정 — 2026-10-10

사용자의 ‘수정사항 수정’ 요청으로 최신 로컬 main `a8aabc3`을 UX 담당 워크트리 `codex/ux-coordinator`에 반영한 뒤 실제 SwiftUI 두 화면을 수정했다. 근거는 [후속 파일럿](subagent-followup-pilot-20261010.md)의 진행/저장 의미 불확실성과 달력 아래 일지 접근이다. 기존 UI 담당의 구현·통합은 완료 상태이며 이번 후속 요청의 두 화면만 변경한다.

## 변경

- `App/TodayView.swift`: 활성 운동이 있을 때만 ‘진행 중 · 완료/전체 세트’와 진행바를 표시한다. 활성 운동이 없으면 오늘 계획의 총 세트 수와 운동 시작 안내를 표시해, 새 세션이 아닌데도 0/N 진행 상태처럼 보이는 문제를 줄인다.
- 오늘 저장 요약은 `workouts(on: model.currentDate)`의 운동 횟수와 `session.done` 합계로 표시한다. 예를 들어 계획 2세트·저장된 일지 3회/5세트는 ‘오늘 계획 · 총 2세트’와 ‘오늘 일지에 3회 · 5세트 저장됨’으로 구분한다. 이전 날짜에 시작한 진행 중 운동은 기존 세션의 진행/계획을 유지한다. 수동·부분 완료 일지를 포함하고 휴식일의 저장 요약도 유지한다.
- 저장 요약과 새 운동 버튼은 작은 화면 또는 접근성 글자 크기에서 세로로 배치한다.
- `App/WorkoutJournalView.swift`: 달력 위에 선택 날짜·저장한 운동 횟수·완료 세트 합계와 ‘세트별 기록 보기’ 버튼을 둔다. 달력 아래까지 스크롤하거나 날짜를 길게 누르지 않아도 기존 날짜별 상세 sheet를 연다. 빈 날짜는 기존 ‘운동 기록 없음’ 화면을 사용한다.
- 일지 카드에 ‘세트별 기록 보기’ 문구와 접근성 힌트를 추가한다. 기존 NavigationLink, 전체 목록, 날짜 길게 누르기, 추가/삭제/세트 편집 동작을 보존한다. 원격 탭 미반영을 제품 탐색 실패로 확정해 터치 처리기를 바꾸지는 않았다.

## 검증과 적용 상태

제품 코드와 기존 모델의 날짜/집계/저장 조건을 대조하고 별도 읽기 전용 subagent로 최종 diff를 검토했다. 집계 날짜, 수동/부분 완료 일지, 휴식일, 자정 이후 활성 세션, 빈 날짜 상세와 큰 글자 조건을 코드 수준에서 확인했다. `git diff --check` 및 staged diff 검사 통과. 표시·기존 상세 진입만 바꾸는 작은 UI 수정이며 데이터를 쓰는 새 로직이나 모델 변경은 없다. 구현을 그대로 복제하는 테스트는 추가하지 않았다.

Windows 환경에서 `swift`, `swiftc`, `xcodebuild`를 찾지 못했다. 전체 iOS 빌드·XCTest·SwiftUI 실제 렌더·iPad 수정 화면 확인은 미실행이다. 코드 검토를 컴파일 성공이나 실기기 회귀 통과로 보고하지 않는다. 이전 파일럿의 화면은 수정 전 설치 앱이며, 현재 설치 앱 SHA도 미확인이므로 이번 변경의 증거로 사용할 수 없다.

본인 두 Swift 파일과 결과 문서/색인만 커밋하고 공통 UX 잠금 스크립트로 로컬 main에 통합한다. 최종 커밋·통합 상태는 완료 응답에 기록한다. 원격 push·배포·설치는 수행하지 않는다. 수정된 앱을 빌드·설치한 뒤 진행/저장 의미 설명과 달력 위 상세 버튼을 같은 목표로 재검증해야 한다. 원격 탭/영상 최신성 문제의 진단과 이전 파일럿 상세 pending은 별도로 남아 있다.
