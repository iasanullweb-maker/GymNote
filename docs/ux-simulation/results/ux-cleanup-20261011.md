## 최고기록 저장과 동기화

기존 일지 성취는 `recordWorkouts`에 보존한다. 성취 사본은 세트 최대값과 합계(`recordTotals`)만 남겨 전체 세트 배열·무게·계획 상세의 중복을 줄인다. 일지 추가·수정·삭제는 이 보존 사본을 다시 계산하지 않는다. 기존 수동 최고는 `bestRecordEntries`에 따로 보존한다. 구버전 클라이언트의 수동 기록 추가·수정은 원본 `records`에 남기되 보존된 최고를 올리지 않는다. 오늘 실행에서 자격을 얻은 측정 후보만 이 최고 기준에 추가한다.

실행 중 오늘 완료한 세트는 `recordReps`, 라운드·측정 종목은 `recordEntries`에 자격 있는 후보를 남기고 운동 저장 시 반영한다. 오늘 진행 중 실행 화면에서 수정한 횟수는 후보도 수정한다. 과거 일지 편집과 위젯 완료는 새 최고 후보로 인정하지 않는다. 세트 되돌리기와 동시 위젯 입력 병합에서 취소된 신규 후보를 제외하며 기존 저장 기록은 제거하지 않는다.

구버전 서버 일지에 새 필드가 없을 때 이미 보존한 성취를 수정된 과거 일지로 덮어쓰지 않는다. 최초 다운로드만 기존 일지로 기준을 만든다. 신규 필드는 기존 JSON의 선택 필드로 추가했으며 운영 SQL 변경은 없다.

마이그레이션 전 파일을 백업한다. 기존 2MB 제한을 유지한다. 성취 사본 추가로 캐시가 제한을 넘으면 원본을 덮어쓰지 않고 읽기 가능한 메모리 사본을 반환한다. 이후 저장·서버 업로드에도 제한은 적용되므로 용량 경계의 성공적인 동기화까지 검증됐다고 보고하지 않는다.

## 계획 추가 편의성 제안

1. **우선 제안:** 날짜 선택 후 운동 여러 종목을 한 번에 선택하고, 같은 화면에서 각 운동의 세트·횟수를 설정해 저장. 현재 종목마다 선택·편집·닫기를 반복하는 횟수를 줄인다.
2. **빠른 복사:** 최근 계획과 지난주 같은 요일 계획을 미리보기로 보여준 뒤 선택 날짜에 복사. 기존 계획을 덮어쓸지 뒤에 추가할지 저장 전에 명확히 표시한다.
3. 길게 누르기에서 기록 없는 날 바로 계획 편집을 여는 동작은 이번에 반영했다. 위 1·2의 추가 화면 개편은 제안이며 구현 완료로 표시하지 않는다.
