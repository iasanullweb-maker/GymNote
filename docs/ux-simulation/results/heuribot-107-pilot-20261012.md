# 0.1.107 가상 사용자 화면 검증 — 2026-10-12

## 범위와 결과

사용자가 107 버전 표시·운동 시작·세트 완료 버튼 활성화를 확인하고 가상 사용자 검증을 요청했다. 실제 iPad의 PNG로 독립 `fork_turns=none` 사용자 조건 4개를 실행하고, 모두 종료한 뒤 독립 기획자 1개가 실제 이미지·모든 사용자 응답 원문·행동 기록을 대조했다. 실제 사람 4명의 사용성 시험·성공률은 아니다. 제품 코드를 변경하거나 새로 배포하지 않았다.

화면 인터뷰 2개와 읽기 전용 탐색 2개다. 부모가 수행한 사용자 제안은 탭 3회·스크롤 1회, 준비/최종 복원 탭 2회는 별도로 기록했다. 운동 시작·세트 완료·횟수 변경·저장·추가·편집·삭제·날짜 선택·친구/계정·외부 앱 접근을 실행하지 않았다.

| 조건 | 실제 전달 화면·행동 | 관찰과 한계 |
|---|---|---|
| 처음 보는 사용자, 실행 화면 인터뷰 | execution-001 한 장, 조작 없음, 첫인상/상태/다음 행동 후 버튼별 기대 추가 질문 | 시작 전 상태와 시작 진입점 이해. 시작 전에도 완료 버튼이 주황색이라 눌러도 되는지 불확실. ±는 횟수, 완료는 한 세트로 예상했으나 원 표시와 조절 대상은 추측이라고 밝힘 |

두 인터뷰의 후속 질문은 ±와 완료를 직접 지목했다. 이 질문에 대한 올바른 예상은 자발적으로 버튼 의미를 발견했다는 증거가 아니다. 실제 버튼 기능·계산·저장 성공도 검사하지 않았다. 계획의 추가 진입점을 찾은 뒤 편집 화면은 열지 않았다.

## 독립 기획자의 개선 후보

1. **시작 전 조작 상태와 의미.** 시작 전 문구는 이해됐지만 세트 완료 조작은 사용할 수 있어 보였다. 시작 전 비활성 표현을 명확하게 하고 필요할 때 짧은 ‘운동 시작 후 완료 가능’ 안내, 횟수 조절 대상·완료 세트 표식을 검토한다. 동일 시작 전 화면에서 첫인상/다음 행동을 먼저 묻고, 별도 버튼 질문을 뒤에 하는 순서로 재검증한다. 두 합성 조건의 불확실성은 실제 사람의 발생률로 표현하지 않는다.
2. **계획 설정 진입점 노출.** 달력이 첫 화면을 차지하여 한 번 스크롤한 뒤 진입점을 찾았다. 탐색 실패는 아니며, 달력 위 선택 날짜 계획 설정 버튼도 제공하는 안을 검토한다. 같은 기기·방향·초기 상태에서 실제 진입점 발견을 다시 관찰한다.
3. **기록의 단위와 그래프 범위.** 출처 단서는 이해됐지만 ‘횟수’·최고값 포함 기준·그래프 대상이 충분히 드러나지 않았다. 부모의 사후 코드 읽기에서 PlanCalendarView의 `workouts.count`를 ‘회’로 표시함을 확인했다. 운동 일지 개수임을 구분하는 문구와 최고값/그래프 대상 설명을 검토한다. 데이터 계산 정확성은 별도 검사한다.

위 내용은 개선 후보이며 구현하지 않았다. 기획자에게 개발 코드·기대 결론·과거 보고서를 주지 않았다. 본문의 코드 단위 확인은 기획 검토가 끝난 뒤 부모가 한 별도 검토다. 계획 응답의 ‘計画’ 표기는 화면 ‘계획’과 다른 합성 응답 표기이며 제품 문자 오류로 분류하지 않는다.
