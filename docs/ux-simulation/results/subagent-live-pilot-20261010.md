# 직접 화면 subagent 파일럿 — 2026-10-10

사용자의 “연결 확인 뒤 가상 사용자 작업을 subagent로 시작” 요청에 따라, 기존 읽기 전용 파일럿을 실제 iPad 화면으로 실행했다. 초보·주의 분산 조건의 서로 다른 목표 4개를 **독립 `fork_turns=none` 사용자 subagent 4개**로 직렬 진행하고, 모두 종료한 뒤 독립 기획자 1개가 증거를 검토했다. 실제 사람 4명의 사용성 시험이나 성공률을 뜻하지 않는다. 제품 코드는 변경하지 않았다.

## 환경·증거

- 로컬 실행 근거: `.worktrees/ux-coordinator/simulation/runs/usb-pilot-stable-20261010-1640/`. 시작 16:36 KST, 최종 화면 16:53 KST. run ID의 1640은 식별자이며 정확한 시작 시각이 아니다. 화면·중계·모델 대기 시간을 사람의 수행 시간으로 해석하지 않는다.
- 사용자 확인: 현재 화면은 테스트 내용이며 탭은 실행·계획·기록·친구·설정 순서. 시험은 실행·계획·기록의 탭 이동과 스크롤만 수행했다. 저장·세트 완료·운동 시작·날짜 선택·계정·친구·설정 변경은 수행하지 않았다.
- 기기에서 조회한 OS: 27.2, build 24B5089g. USB 영상 2432×1680 pixels, 입력 변환 270°. 글자 크기는 미확인이다. 앱 빌드·소스 SHA는 식별하지 못해 null이며 뷰어 구현 `9da3205`와 구분한다. 실제 iPad에 표시된 UI를 확인했으나 이 증거로 특정 Swift 빌드를 검증했다고 주장하지 않는다.
- 사용자 역할에는 persona·현재 화면·현재 목표만 제공했다. 지정 현재 PNG의 이미지 관찰만 허용하고 저장소·다른 파일·기기·브라우저·서버 조작은 금지했다. 부모만 입력을 중계했다. 첫 과제는 초기 화면 미제공 중지와 사람 전사를 거친 뒤 직접 이미지로 전환했다. 나머지 과제는 처음부터 직접 이미지였다.
- 사용자 역할 응답 14회(초기 화면 미제공/전사/이미지 전환 포함), 기획 응답 1회. 정확한 모델 식별자·API 요청·토큰 사용량은 미확인으로 null이다. 사용자 제안에 따른 실제 조작은 **탭 6회 + 스크롤 1회**이며 과제당 1~2회다. 초기 화면 복원·관찰 준비 조작은 제외했다.
- `pilot.json`, `role-observations.json`, `actions.jsonl`, `images.json`, `planner-review.md`, 실제 PNG 13개를 로컬 run에 보관한다. 마지막 PNG는 부모가 실행 시작 화면으로 복원한 증거다. 이미지·기기 식별자·개인 원본은 Git에 넣지 않는다. 고정 demo-v1로 초기화한 실험이 아니므로 동일 데이터 재현을 보장하지 않는다.

## 실제 경로와 판정

| 과제 | 실제 사용자 제안 경로·증거 | 확인한 범위 |
|---|---|---|
| 초보: 예정·수행 구분 | 실행→계획→기록 (`screen-001`, `003`, `004`) | 계획 달력의 운동/휴식과 운동 일지의 횟수·세트/기록 없음을 구분해 설명했다. 화면 이해 관찰 |
| 독립 초보: 보관 단서 | 실행→기록→아래 스크롤 (`005`, `006`, `007`) | 저장 문구와 날짜별 기록을 보고 해당 테스트 일지 카드를 찾았다. 실제 저장 지속성·상세 값은 미검증 |
| 주의 분산: 오늘·다음 정보 | 실행→계획 (`008`, `009`) | 오늘 날짜와 계획상 운동 나열 순서를 설명했다. 실행 화면의 현재 진행 상태는 확신하지 못했다. 실제 다음 세트 수행은 미검증 |
| 독립 주의 분산: 문맥 복귀 | 계획→실행→계획 (`010`, `011`, `012`) | 이전 선택 날짜와 운동 목록을 다시 설명했고 같은 날짜 강조가 유지됐다. 인간의 주의 중단을 시험한 것은 아님 |

문맥 복귀 과제는 돌아갈 문맥을 설정하기 위해 계획 화면에서 시작했고, 나머지는 실행에서 시작했다. 목표도 서로 달라 역할 간 행동 수·성과 수치 비교에 사용하지 않는다. 날짜 선택과 오늘 컨트롤은 누르지 않았으므로 해당 조작의 어려움이나 실패를 주장하지 않는다. 마지막에는 실행 탭으로 복원했고 테스트 제목·저장 문구·진행 표시가 시작 화면과 같이 보였다(`013`). 이 화면 일치가 데이터베이스 보존 검사는 아니다.

## 기획자 검토와 다음 후보

기획자는 기록 JSON과 참조된 실제 이미지 9개를 직접 대조했다. 구현·과거 보고서로 사용자에게 정답을 주지 않았다. 최대 3개 후보를 제안했으며 **제품 결함 확정은 아니다**.

1. **진행 수치와 저장 표시 의미 — 우선 재검증.** 실행에서 `0 / 2 세트`와 `운동 일지에 저장됨`이 공존한다. 초보 첫 과제와 주의 분산 첫 과제에서 진행/수행 상태가 불확실하다는 발언이 나왔다. 표시의 실제 데이터 의미를 먼저 확인하고, 각각 어느 세션·내용을 뜻하는지 설명하는 안을 검토한다. 완료·새 세션 같은 상태를 근거 없이 붙이지 않는다. 같은 테스트 상태·직접 화면 입력으로 의미 설명과 다음 행동 찾기를 반복한다.
2. **기록 상세 진입 — 탐색 가설.** 초보는 일지 카드를 찾았지만 세트별 상세 값은 확인하지 않고 멈췄다. 날짜 길게 누르기 안내와 카드의 화살표는 보인다. 이번 범위가 탭 이동/스크롤로 제한됐으므로 상세 진입 실패라고 볼 수 없다. 읽기 전용 상세 열기를 허용한 별도 목표에서 실제 진입을 검증한 뒤 목적이 드러나는 표시를 검토한다.
3. **오늘·선택 날짜 구분 — 낮은 우선순위의 예방 가설.** 같은 색 계열의 오늘 숫자와 선택 날짜 강조가 있다. 이번에는 오늘 식별과 날짜 복귀 설명이 맞았다. 실패 증거가 없으며 텍스트 보조 표시 필요성은 같은 조건 반복으로 확인한다.

## 기술 사건·검증·남은 범위

첫 계획 입력 직후 `002`는 이전 화면이었고, 추가 관찰 `003`에서 계획 도착을 확인했다. 같은 탭을 다시 누르지 않았으며 이를 사용자 실수나 제품 탐색 실패로 합산하지 않았다. 초반 개별 영상 구독을 통한 이미지 추출은 세션 시작 복구를 유발했다. 이후 단일 지속 디코더 구독으로 전환했고 화면 요청 이후 도착한 프레임만 저장했다. 같은 worker에서 generation 1→4 변화가 있었으므로 전체 파일럿을 무재시작 시험으로 표현하지 않는다. 이후 지속 중계 구간의 확인된 generation은 4였고 worker 교체·복구 실패·gap/reorder/corrupt는 관찰하지 않았다. 본인 중계 구독은 종료하고 사용자의 Chrome 뷰어 서버는 유지했다.

검사: 과제 4개·독립 역할 4개·사용자 응답 14회·기획 응답 1회, 실제 조작 7개와 전후 이미지 참조, PNG dimensions/SHA-256, 금지 조작 없음, 앱 SHA null·usage null, Markdown 로컬 링크와 `git diff --check`를 확인했다. 관련 프롬프트에는 지정 PNG 관찰 예외를 명시했다. 문서·프롬프트만 변경했으므로 제품 테스트나 전체 iOS 빌드·XCTest를 재실행하지 않았다. 파일 검토·커밋 후 공통 잠금 스크립트로 로컬 main에 통합하며 최종 해시는 완료 응답에 기록한다. 원격 push·배포는 수행하지 않는다.
