# Windows USB iPad 검증 — 2026-10-09

## 목표와 현재 판정

Mac/Xcode 없이 사용자의 실제 iPad에서 GymNote 화면을 관찰하고, 원격 터치로 사용자 시나리오를 검증한다. BrowserStack의 2분 체험 제한을 피하는 로컬 경로다.

- 사용자와 에이전트 모두 실제 GymNote 설정 화면을 확인했다. HTML 모사 화면이 아니다.
- 원격 터치 성공은 미확인이다. 실행·계획 탭 클릭 후에도 설정 화면이 유지됐다.
- 영상이 반복 정지·복구되어 아직 자동 사용자 실험에 사용할 수준으로 검증되지 않았다.
- 실제 기기는 iPadOS 27.2, 설치 앱은 0.1.85/build 85다. 클라우드 조사 대상 0.1.88과 버전이 다르므로 이 결과로 build 88의 시작 문제를 해결했다고 판단하지 않는다.

## 로컬 실행 환경

기존 Apple Mobile Device Service와 USB 연결을 사용했다. Python 3.14 환경의 의존성 빌드가 실패하여 저장소의 무시 경로 `.validation-tools/ipad-usb/python312/`에 공식 Python 3.12.10 embeddable과 pymobiledevice3 11.26.0을 설치했다. 전역 Python·PATH·Git 설정은 변경하지 않았다.

기기의 개발자 모드는 이미 켜져 있었다. `mounter auto-mount`로 개발자 디스크 이미지를 준비했으며, 화면 서버는 userspace 터널로 연결됐다.

```powershell
.\.validation-tools\ipad-usb\python312\python.exe -m pymobiledevice3 developer core-device display serve-web --bind 127.0.0.1 --http-port 8766 --no-audio
```

PC Chrome에서 `http://127.0.0.1:8766/`를 연다. 서버 종료는 실행 터미널의 Ctrl+C를 사용한다. `--no-motion-idr` 추가도 비교했으나 끊김은 재발했다. 현재 프로세스의 수명·PID는 세션에 종속되므로 재접속 시 다시 확인한다.

## 관찰한 문제

- 서버가 `no AU progress`를 기록하고 약 5~8초 정지 후 스트림을 재시작했다. 이는 영상 연결 증거이며 GymNote 앱 충돌 증거는 아니다.
- Windows 창 위치가 바뀌어 최초 클릭은 대상 창 불일치로 거부됐다. 창을 다시 관찰한 뒤 클릭을 재시도했다.
- 관찰한 실행 탭 좌표로 로컬 `/touch`의 단일 tap도 비교했다. 서버의 `ok` 응답은 큐 접수이며 UIKit 터치 성공을 증명하지 않는다.
- backboardd의 digitizer 거부 메시지만 잠깐 필터링했으나 출력은 없었다. 원인 배제 근거로 사용하지 않는다. 로그 조회 프로세스는 종료했다.
- Windows에서는 AAC-ELD 디코더가 실패했다. `--no-audio`는 뷰어의 자동 소리 재생을 끄는 옵션으로, 기기 오디오 스트림 생성 자체를 막는 옵션이라고 설명하지 않는다.

## 개인정보와 다음 검증

리스닝 주소를 `127.0.0.1:8766`으로 재확인했다. LAN 공개, 클립보드 동기화, 보안 설정 변경, 사진·연락처·메시지·전체 백업 수집은 수행하지 않았다. 화면 캡처에는 보이는 내용이 포함되므로 GymNote만 표시하고 테스트 데이터로 실험한다. 비밀번호가 없는 로컬 서버는 PC의 다른 프로세스에 노출될 수 있어 실험 종료 시 종료한다.

1. 사용자가 iPad에서 실행 탭을 직접 눌렀을 때 PC 영상도 바뀌는지 비교한다.
2. 영상은 정상이고 원격 터치만 실패하면 화면 회전 좌표·HID 세션 상태·기기 OS 호환성을 조사한다.
3. 영상 안정성 및 왕복 터치를 입증한 뒤 테스트 데이터 시나리오를 실행한다. 앱 재설치로 기존 사용자 데이터를 지우지 않는다.

앱 코드 변경·전체 iOS 빌드·XCTest·원격 push·배포는 수행하지 않았다. 설치 파일·원본 기기 로그·기기 고유 식별자는 Git에 포함하지 않는다.
