# GymNote 0.1.99 배포 후 확인 체크리스트

작성: 2026-10-11. 대상: **0.1.99 / build 99**, 2026-10-10 배포, 코드 `9580a75`.

먼저 1~3번을 확인하고, 관리자·일반 테스트 계정을 준비한 뒤 나머지를 진행한다. 각 항목은 기대 결과까지 직접 확인한 뒤 체크한다. 일부만 확인했으면 항목을 나누어 나머지는 미완료로 유지한다. 설치·자동 테스트·배포 성공만으로 사용자 확인을 완료 처리하지 않는다.

## 1. 설치·첫 실행·기록 보존 — 먼저 확인

- [ ] **iPad 설치:** AltStore 소스를 새로고침해 0.1.99로 업데이트하고, 설치된 버전/빌드를 확인한다. 앱 아이콘을 눌렀을 때 첫 화면이 정상으로 열린다.
- [ ] **업데이트 전후 보존:** 같은 계정의 운동 일지·최고 기록·계획·일상·진행 중 운동이 유지된다. 앱을 완전히 종료하고 다시 열어도 기록이나 완료 수가 늘거나 줄지 않는다.
- [ ] **iPhone 준비:** iPhone에 AltStore와 헬스노트 소스를 등록하고 같은 0.1.99를 설치한다. 절차는 [설치 안내](../../../README.md#설치-altstore-소스-추천)를 따른다.
- [ ] **두 기기 계정:** iPad와 iPhone에서 같은 GymNote 계정에 로그인했는지 확인한다. Apple ID와 GymNote 계정을 혼동하지 않는다.

## 2. 이번 수정 화면·저장 흐름

- [ ] **시작 전 실행 화면:** 활성 운동이 없을 때 ‘오늘 계획 · 총 N세트’가 계획과 맞고, 진행 중 상태처럼 보이지 않는다.
- [ ] **진행 중 실행 화면:** 운동 시작 후 완료/전체 세트와 진행도가 실제 체크에 맞게 바뀐다. 자정이 지나도 진행 중 운동은 시작한 날짜의 계획을 유지한다.
- [ ] **오늘 저장 요약:** 저장한 일지 횟수와 완료 세트 합계가 실제 일지와 맞고, 오늘 계획의 총 세트와 구분된다. 여러 번 운동하거나 일부만 완료한 기록도 맞다.
- [ ] **달력 위 상세 진입:** 기록 탭에서 날짜를 선택하고 ‘세트별 기록 보기’를 누르면 해당 날짜의 일지가 열린다. 기록이 없는 날짜는 빈 상태를 표시한다.
- [ ] **일지 카드 상세:** 카드에서도 상세에 들어갈 수 있고, 실제 횟수·무게·완료 세트가 저장 내용과 맞다. 원격 영상이 멈춘 경우에는 직접 기기에서 같은 동작을 확인해 구분한다.
- [ ] **함께 보기:** 같은 날짜에 운동·일상을 만들고 양쪽 계획 화면에서 함께 보기를 켜면 달력·날짜 상세·주간 목록에 둘 다 나온다. 끄면 해당 분야만 보인다.
- [ ] **선택 유지·날짜 미정:** 함께 보기 선택이 탭/분야 전환과 재실행 후 유지된다. 날짜 미정 일상은 별도 목록에 있고, 날짜를 정하면 해당 달력에 표시된다.
- [ ] **월 이동·오늘 갱신:** 월 이동 시 선택 날짜와 상세도 같이 이동하고, 31일→2월은 유효한 마지막 날짜로 보정된다. 자정 경과 또는 다음 날 복귀하면 오늘 계획·일상이 갱신된다.
- [ ] **저장 실패 후 재시도:** 격리된 테스트 환경에서 실패 시 편집 화면과 입력을 유지하고, 정상 복구 후 재시도하면 저장된 뒤 닫힌다. 실제 기록 파일을 훼손해 실패를 만들지 않으며, 안전하게 재현하지 못한 경우 미확인으로 남긴다.

## 3. iPad ↔ iPhone 동기화

테스트 데이터로 진행한다. 충돌 선택은 해당 테스트 변경만 대상으로 하고, 개인 기록을 시험용으로 덮어쓰지 않는다.

- [ ] **변경 왕복:** 한 기기에서 테스트 계획·일상·운동 기록을 바꾸면 다른 기기에 반영된다. 반대 방향도 확인하고, 백그라운드 복귀·재실행 후 같은 내용이 보인다.
- [ ] **서로 다른 항목 동시 변경:** 두 기기를 오프라인으로 둔 상태에서 서로 다른 항목을 수정하고 재연결하면 양쪽 변경이 모두 남는다.
- [ ] **같은 항목 충돌:** 두 기기에서 같은 항목을 다르게 수정하고 재연결하면 변경 선택 안내가 나온다. 고른 결과가 양쪽에 반영되고, 선택 전 조용히 덮어쓰지 않는다.
- [ ] **진행 중·편집 중:** 운동 중 다른 기기를 열어도 완료 수가 줄거나 중복되지 않는다. 편집 화면을 30초 넘게 열어 두어도 입력이 갑자기 바뀌지 않고, 편집 종료 후 동기화된다.
- [ ] **모바일 데이터:** iPhone Wi-Fi를 끄고 LTE/5G만으로 변경을 주고받는다. 연결 상태가 정상으로 표시되고 안내 문구가 ‘인터넷’ 기준이다.
- [ ] **기기별 일상 알림:** ‘이 기기에서 알림 받기’를 켠 기기에서만 일상 알림이 울린다. 신규 iPhone과 업데이트한 iPad의 초기 설정을 확인하고, 끄면 그 기기의 일상·10분 뒤 알림만 취소되며 휴식 알림은 유지된다.

## 4. 공통 종목·운동 개선

- [ ] **관리자 종목 노출:** 관리자 테스트 계정에서 활성 공통 종목을 추가하면 일반 계정의 운동 목록·계획 운동 추가·지난 일지 불러오기에 모두 나타난다. 개인 목록 추가와 공통 목록 추가는 구분된다.
- [ ] **공통 목록 갱신·권한:** 새로고침·활성 중 주기 갱신·앱 복귀 후 최신 목록이 보인다. 일반 계정/게스트에 관리자 쓰기 기능이 없고, 오프라인 캐시와 재연결이 동작한다.
- [ ] **개인 사본 보존:** 공통 종목을 선택해 세트·횟수/시간을 저장하고 재실행해도 유지된다. 관리자가 종목을 수정·중단해도 이미 저장한 계획·일지 사본은 바뀌지 않는다.
- [ ] **지난 운동 참고:** 같은 운동의 적절한 과거 실제 기록을 보여 주고, 횟수 채우기만으로 세트가 자동 완료되지 않는다. 미기록 횟수를 임의의 값으로 채우지 않는다.
- [ ] **종료 요약:** 완료 세트·실제 횟수·시간·운동한 날짜 수가 일지와 맞다. 부분 완료·미기록·무게 변경을 잘못된 성장 수치로 표시하지 않고, 일지 수정/재실행 후에도 일치한다.
- [ ] **기본 루틴·안내:** 루틴 미리보기·추가·취소와 운동 안내가 동작한다. 취소는 계획을 바꾸지 않고, 자세 설명과 외부 자료 링크가 의도한 운동에 해당한다.
- [ ] **운동 대체:** 한 세트 완료 후 대체하면 완료분은 원래 운동에, 남은 세트는 새 운동에 남는다. 이미 저장된 일지와 다른 날짜의 계획은 유지된다.
- [ ] **오래된 대체 화면:** 대체 화면을 연 뒤 위젯에서 세트를 완료하거나 새 운동을 시작하거나 다른 기기에서 계획을 바꾸면, 오래된 화면의 저장은 거부되고 최신 진행·계획이 보존된다.

## 5. 기존 기능 회귀

세부 조작 순서는 [기존 실사용 점검표](../../RELEASE_DEVICE_CHECKLIST.md)를 함께 따른다. 그 문서의 0.1.91 배포 정보는 과거 이력이며, 여기서는 설치한 0.1.99로 확인한다.

- [ ] **세트·운동 순서:** 실제 횟수/무게 입력, 완료/되돌리기, 완료 묶음 이동, 길게 끌기와 이동 취소가 동작한다. 운동 누락·중복 없이 탭 왕복·재실행·위젯 체크 후 순서와 값이 유지된다.
- [ ] **휴식·운동 종료:** 자동/수동 휴식·건너뛰기와 수동/자동 종료의 ‘완료→일지에 저장됨’ 표시가 맞다. 일지는 한 번만 생기고, 0세트 취소는 일지를 만들지 않는다.
- [ ] **기록 입력:** 낮은 기록도 저장할 수 있고 신기록 안내·정수/소수/라운드 규칙·지난 일지 수정·최고 기록 계산이 맞다.
- [ ] **화면·접근성:** iPad 세로/가로/분할 화면, iPhone 작은 화면, 큰 글자에서 배너·탭·마지막 버튼·키보드 입력이 겹치지 않는다. 긴 운동명, VoiceOver, 동작 줄이기도 확인한다.
- [ ] **로그인·계정 분리:** 로그인 복귀/취소/실패, 로그아웃·계정 전환·게스트 가져오기가 동작한다. 기록이 섞이지 않고 가져오기 재시도에 중복이 없다.
- [ ] **친구·그룹·공개:** 두 테스트 계정으로 가입, 요청 처리, 그룹 참여/나가기, 순위, 공개 켜기/끄기를 확인한다. 비참여 계정과 전환 전 계정 정보가 노출되지 않는다.
- [ ] **친구 탈퇴:** 아래 서버 준비 확인 후 테스트 계정에서 진행한다. 성공 시 관계·그룹·공개 기록이 정리되고 개인 기록/앱 로그인은 유지된다. 취소·실패 시 기존 상태를 유지하며 재가입은 새 코드로 시작한다.
- [ ] **계정 삭제:** 테스트 계정에서 준비 화면의 취소/닫기/재진입, 인증 만료·다른 계정 인증 거부를 확인한다. 실제 삭제는 해당 테스트 계정에서만 진행한다.
- [ ] **위젯·Live Activity:** 세트 체크·마지막 세트 종료가 앱에 한 번만 반영된다. 휴식 종료/건너뛰기·운동 종료·계정 전환·재실행 상태가 맞다.
- [ ] **일상·편집 이동:** 반복/예외·완료 기록·알림 완료/10분 뒤 다시, 계정 전환 시 알림 정리가 맞다. 편집 중 이동 제한이 저장/취소 후 풀리고 상세 화면 왕복 시 진행·선택 날짜가 유지된다.

## 6. 서버 선행 확인 — 개발 담당

이 배포에서 운영 SQL은 적용하지 않았다. 아래는 기기 조작과 별개로 상태를 확인할 항목이다.

- [ ] 운영의 `202610090002_integer_records.sql` 적용 여부를 읽기 전용으로 확인한다. 기존 기록의 정수 규칙과 권한이 맞는지 확인한다.
- [ ] 기록상 미적용인 `202610090003_social_withdraw.sql`의 현재 상태를 확인한다. 필요하면 별도 승인 범위에서 적용하고 authenticated/anon 권한·FK·친구 탈퇴 동작을 확인한다. 이미 적용된 마이그레이션이나 테스트 SQL을 운영에 재실행하지 않는다.

## 7. 가상 사용자 파일럿·검증 환경

- [ ] **수정 앱 파일럿:** 설치 버전을 기록하고 새 사용자 역할로 실행→계획→기록→친구→설정 탐색을 다시 수행한다. 기록 상세 진입과 세트별 값 확인을 포함하고, UI 실패와 원격 입력/영상 지연을 구분한다. [후속 파일럿](subagent-followup-pilot-20261010.md)에서 미확정인 항목을 다시 확인한다.
- [ ] **USB 다른 방향:** 이미 확인한 가로 방향 외의 반대 가로·세로에서도 클릭과 드래그 위치가 화면과 맞다.
- [ ] **USB 장기·반복 복구:** 장시간 연결, 긴 분리, 반복 단절, 잠긴 기기의 재연결을 각각 확인하고 수동 새로고침 여부와 복구 시간을 기록한다. 기존 10분 관찰·짧은 단절 자동 복구·복구 후 양쪽 화면 반영은 이미 사용자 확인된 이력으로 유지한다.

별도 작업의 확인 대기도 보존한다. 아래 항목은 앱 배포 성공으로 완료되지 않는다.

- [ ] **텔레그램 자동화:** 봇/허용 사용자 설정 후 메모 수신, 작은 문서 작업의 접수→검토→로컬 통합→결과 알림과 상태/중지 흐름을 확인한다. 외부 연결·모델 실행 범위를 먼저 정하고 [인수인계](../../../HANDOFF.md)의 연결 절차를 따른다.
- [ ] **클라우드 iPad 환경:** 사용하기로 한 경우 BrowserStack 연결·IPA 설치/재서명·첫 실행·위젯/알림/App Group 지원을 확인한다. 웹 모사 결과로 실제 기기 확인을 대체하지 않는다.

## 확인 결과 기록

각 항목에 `확인일 / 기기·OS / 앱 버전 / 재현 순서 / 기대 결과 / 실제 결과`를 덧붙인다. 사용자가 명시적으로 확인한 범위만 체크하고, 문제가 다시 보고되면 해당 항목을 미완료로 되돌린다. 개인정보·친구 코드·토큰·실제 건강 기록은 결과 파일에 넣지 않는다.

예: `2026-10-11 / iPad·OS 버전 / 0.1.99 / 기록→날짜 선택→세트별 기록 보기 / 해당 날짜 상세 / 정상`.

이 파일은 체크리스트 작성 결과이며 새 실기기 시험·서버 변경·재배포를 수행했다는 뜻은 아니다. 현재 [할 일·사용자 확인 대기 목록](../../../TODOLIST_HANDOFF.md)과 관련 항목의 확인 범위를 함께 갱신한다. 인쇄용 PDF는 작성 당시 사본이며 최신 상태는 Markdown 문서를 따른다.
