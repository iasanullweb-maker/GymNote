# Subagent 실기기 사용성 파일럿

Windows USB 뷰어의 현재 가로 방향은 사용자 클릭·드래그 확인을 받은 **270°**다. 10분 관찰·짧은 USB 단절 자동 복구는 [연결 검증](../results/usb-idle-recovery-validation.md)에서 확인했으며 장기 무중단 보장은 아니다. 이 파일럿은 부모가 실제 화면과 입력을 중계하는 합성 탐색이며 기존 dry-run CLI나 demo-v1 fixture 실행과 구분한다. 실제 앱 SHA가 확인되지 않으면 null로 기록하고 뷰어 Git SHA로 대체하지 않는다.

## 준비와 역할

- `plan.json`: 초보 사용자와 주의 분산 사용자, 각각 목표 2개.
- `user.md`: 두 역할이 공유하는 입력·행동 경계.
- `planner.md`: 실행 후 근거를 검토하는 기획자.
- 준비 subagent는 역할 설계를 검토한다. 실제 사용자 subagent는 **fork_turns=none**으로 새로 만들고 `user.md`, 해당 context, 현재 한 화면, 현재 목표만 전달한다. 저장소 접근과 기기 조작 도구는 금지한다. 부모가 명시한 현재 테스트 PNG 한 장의 `view_image` 관찰만 예외로 허용할 수 있다. 부모가 도구 사용과 제안을 검토하며 이는 기술적 격리 보장이 아닌 실행 규칙이다.

저장소 루트에서 로컬 세션을 준비한다. 기기 조작·모델 호출은 하지 않는다.

```powershell
.\.validation-tools\ipad-usb\python312\python.exe scripts/ux_simulation_prepare_pilot.py
```

새 `simulation/runs/usb-pilot-*/`에 조건·목표별 시작 프롬프트·행동 로그 양식을 만든다. 출력은 Git 제외이며 자동 API 연결이나 기존 session.schema.json 결과가 아니다. 요청/토큰 수를 알 수 없으면 null로 두며 0으로 꾸미지 않는다.

## 실행 순서

1. GymNote를 전면에 두고 뷰어를 새로고침한다. 개인 정보가 없는 합성/빈 상태의 실행 화면을 부모가 확인한다. 실제 기록이 보이면 화면을 전달하지 않는다. 상태 변경이 필요한 데이터 초기화는 별도 범위다.
2. 한 사용자·한 과제씩 실행한다. 같은 초기 화면과 화면 크기를 유지하며 앱/OS 빌드, 방향, 글자 크기와 시작 시각을 기록한다. 다른 사용자의 결과는 전달하지 않는다.
3. 사용자 제안 하나를 부모가 허용 범위와 현재 화면으로 확인한다. 허용된 조작만 수행하고 전후 화면과 실제 수행 여부를 기록한 뒤 다음 화면을 전달한다. 새 화면 없이 성공 처리하지 않는다. iPad 입력은 단일 부모만 한다.
4. 과제당 실제 조작 최대 8회, 같은 행동 두 번 반복 후 진전 없으면 중단한다. 두 번째 사용자의 문맥 복귀 과제는 앱 내부의 허용 탭 이동만 사용한다. PC 앱 전환이나 외부 앱으로 주의 중단을 흉내내지 않는다.
5. 연결/좌표 장애는 입력을 멈추고 technical-blocked로 기록한다. 복구 후 같은 상태가 확인돼야 재개한다. 개인정보·외부 화면·변경 가능 행동은 즉시 중단한다.
6. 기획자는 실제 증거만 검토해 개선 후보와 재검증 과제를 정리한다. 제품 변경은 다음 작업으로 분리한다.

## 기록과 한계

`actions.jsonl`에는 taskId, step, proposal, executed, beforeEvidence, afterEvidence, observedResult, interruption을 기록한다. 화면 파일은 개인정보가 없는 경우에만 로컬 run 폴더에 저장한다. 결과는 observed/not-found/not-evaluated와 technical-blocked/scope-blocked를 구분한다. 단계별 증거 없이 사용성 성공을 선언하지 않는다.

초기 준비는 역할·실험 조건·로그 구성까지였으며 준비 명령만으로 실제 합성 사용자 자유 탐색과 기획 평가가 실행됐다는 뜻은 아니다. 실제 수행한 후속 파일럿은 아래 결과를 따른다. 격리 데이터·초기화·저장 전후 상태 관찰을 마련해야 운동 기록·편집·취소 실험으로 확장할 수 있다. 기존 runner의 live 어댑터는 여전히 미구현이다.

## 2026-10-10 직접 화면 전달 실행

사용자가 테스트 내용임을 확인한 실제 iPad 화면으로 독립 사용자 과제 4개와 종료 후 독립 기획자 검토를 실행했다. [실행 결과](../results/subagent-live-pilot-20261010.md)를 따른다. 준비 명령 자체가 이 실행을 자동으로 수행하는 것은 아니다.

이번 부모 중계에서는 로컬 영상 스트림을 PyAV로 디코딩해 현재 테스트 PNG를 Git 제외 run에 저장하고, 지정한 PNG만 각 사용자에게 제공했다. 처음의 개별 화면 추출은 구독 시작 복구를 유발했으므로 이후에는 단일 지속 구독을 유지했다. 입력 직후에는 영상 갱신을 기다리고 실제 선택 탭을 확인했다. HTTP 200은 입력 큐 수락일 뿐 화면 전환 증거가 아니다. 부모의 초기 화면 복원 조작은 사용자 행동 수에 포함하지 않았다. 임시 중계 도구는 `.validation-tools/ipad-usb/`에 있으며 범용 live 실행기나 제품 기능으로 통합한 것은 아니다.
