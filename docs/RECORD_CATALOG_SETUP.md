# 공통 최고 기록 종목 설정

최고 기록 종목만 공통 목록으로 관리한다. 루틴의 운동 목록은 개인 편집을 유지한다.

현재 GymNote 프로젝트는 2026-10-09에 공통 종목 마이그레이션·관리자 지정·서버 권한 확인을 완료한 기록이 `HANDOFF.md`에 있다. 아래는 새 프로젝트 설정 절차이며 기존 프로젝트에 마이그레이션을 반복 실행하지 않는다. 이번 문서 대조에서 운영 DB를 재조회하지 않았다.

## 서버 적용

기존 계정 마이그레이션 `202610080001_accounts.sql` 적용 후, Supabase SQL Editor에서
`supabase/migrations/202610080002_record_catalog.sql`을 실행한다. 푸쉬업·풀업·신디가 초기 등록된다.
앱의 기존 Supabase URL과 publishable key를 그대로 사용하며 추가 서버나 관리자 키는 앱에 넣지 않는다.

## 관리자 지정

관리자로 사용할 계정을 앱에서 먼저 가입하고 Supabase Authentication → Users에서 UUID를 확인한다.
프로젝트 관리자가 SQL Editor에서 아래 UUID를 실제 값으로 바꾸어 실행한다.

```sql
insert into public.record_catalog_admins(user_id)
values ('관리자 계정 UUID') on conflict do nothing;
```

권한 해제:

```sql
delete from public.record_catalog_admins where user_id = '관리자 계정 UUID';
```

이 테이블은 일반 사용자에게 읽기·쓰기 권한이 없다. 이메일, 앱에 저장된 플래그,
사용자가 수정할 수 있는 user_metadata는 관리자 판정에 사용하지 않는다.
활성 서버 세션을 확인하며 로그아웃으로 폐기된 세션은 관리자 작업을 할 수 없다.

## 사용

로그인 후 기록 → 공통 종목 안내 → 새로고침. 서버가 관리자 권한을 확인하면 공통 종목 관리 메뉴가 나타난다.
관리자는 추가·이름/설명 수정·표시 순서·사용 중단을 저장할 수 있다.
같은 순서 값이면 ID로 정렬한다. 단위·방식·라운드당 횟수·높고 낮음의 비교 기준은 생성 후
서버에서도 변경을 거부한다. 수행 조건을 바꾸는 경우 새 종목을 만든다. 설명 수정은 오탈자 정정에 사용한다.
동시 수정은 revision 비교로 거부하며, 목록을 새로고침한 뒤 편집 화면을 다시 열어야 한다.

사용 중단은 과거 기록을 삭제하지 않는다. 기록이 있는 중단 종목은 조회·기존 기록 수정/삭제가 가능하지만
새 기록 추가 버튼은 표시하지 않는다. 공통 목록은 공개 정의이며 게스트도 같은 목록을 사용한다.
전체 개인 기록은 기존 계정별 백업에 저장한다. 후속 친구·그룹 기능에서는 공개를 켠 계정의 공통 종목 최고값만 별도 social_records에 제출한다([친구 기능 설정](SOCIAL_SETUP.md)). 전체 개인 백업을 친구에게 공개하지 않는다. 제출값은 서버가 종목·값 범위·접근 권한을 확인하지만 실제 운동 수행을 인증한 기록은 아니다.

## 기존 데이터와 오프라인

개인 종목 정의와 기록은 덮어쓰거나 자동 이관하지 않는다. 공통 종목은 `common-` 접두사의 별도 ID를 사용한다.
과거 개인 기록은 이전 개인 기록 목록에서 조회·수정·삭제할 수 있고 새 기록은 공통 종목으로 입력한다.
공통 기록을 최초 저장할 때 개인 백업에 정의 사본도 보관한다. 화면과 위젯은 서버 목록을 우선 사용한다.
오프라인은 마지막으로 받아 저장한 목록을 사용하며, 최초 연결 전에는 번들 기본 공통 목록을 사용한다.
온라인에서 사용 중단된 종목도 오프라인의 오래된 목록으로 입력될 수 있다. 다음 목록 갱신 후 새 입력은 막히지만
기기에 입력한 기록은 보존한다. 친구 순위 제출 시 서버는 활성 공통 종목 여부를 다시 검증한다.
전체 목록이 비어 있는 서버 응답은 그대로 반영하며 기본 목록으로 되돌리지 않는다.
운동 일지 자동 기록은 기존 기능을 유지한다. 이름이 일치하는 횟수 종목은 개인 화면에서 함께 표시한다.
친구 순위도 이 값을 사용할 수 있지만 수행 조건을 인증한 기록은 아니며 자기 입력 기록이라는 한계를 유지한다.
위젯은 그날 계획한 운동을 표시하고, 운동이 없는 날에는 활성 공통 종목의 앞 3개를 표시한다. 기존 개인 기록은 공통 기록으로 자동 표시되지 않는다.

## 검증

`scripts/test_record_catalog.sql`은 격리된 테스트 DB에서만 실행한다. 실제 프로젝트에는 실행하지 않는다.
`scripts/auth_test_schema.sql` → 두 마이그레이션 → 기존 권한 테스트 → 공통 종목 권한 테스트 순서로 실행한다.
테스트는 일반 사용자/게스트의 수정 차단, metadata 권한 우회 차단, 관리자 생성/수정/중단,
동시 수정, 비교 규칙 변경 차단, 폐기된 세션, 계정 삭제를 확인한다.
`Tests/RecordCatalogTests.swift`는 기존 기록 격리·캐시·빈 목록·위젯·신규 입력을 확인한다.
