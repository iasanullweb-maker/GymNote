# GymNote 일곱 스킬 검증 결과

2026-10-09. 대상은 `.agents/skills/`의 task, verify, ux-check, release, debug, data-change, handoff 스킬과 각 참조·UI 설정이다. 검증 기준은 skill-creator의 구조 검사, 현재 저장소 문서/워크플로/검사 명령, 읽기 전용 독립 시나리오 평가다.

## 발견과 수정

- verify 실행 단계는 실패를 고치라고 지시하면서 검사만 요청의 제품 변경을 금지하고 있었다. 실패 재현·분석과 승인된 구현 수정, 검사만 요청의 근거/제안 보고를 분리했다.
- 같은 모호함을 피하도록 release 실패 처리도 승인된 수정 범위를 명시했다. 배포 준비 상태 확인만 요청되면 제품·테스트를 임의 수정하지 않는다.
- 역할 통합 스크립트가 소스 미추적 파일도 차단한다는 점을 task 참조에 명시했다. 다른 작업 파일을 삭제·커밋하거나 검사·배정을 완화하지 않고 차단과 남은 통합을 보고한다.

## 검사 결과

| 검사 | 확인 범위 | 결과 |
|---|---|---|
| 공식 quick_validate.py | 7개 스킬의 이름·YAML frontmatter·미완성 scaffold | 통과 |
| UI YAML·참조 검사 | 호출 이름, 설명 길이, 자동 선택 기본값, 내부 링크·저장소 경로, HANDOFF 적용 표 | 통과 |
| 전체 본문·참조 검토 | 담당 범위, 실제 CI 트리거, 결과/승인 구분, 커밋·잠금·통합 절차 | 수정 후 충돌 미발견 |
| 독립 시나리오 평가 | 아래 5개 가정 사례; 실제 운영 실행 없음 | 지적 수정 후 관련 사례 재검토 통과 |
| UX 실행기 입력 검사 | Node 24.19.0: `node scripts/ux-sim/run.mjs --validate-only` | 통과; 사용자 4·시나리오 5·60세션 계획 가능, 파일/모델 호출 없음 |
| UX 계약 검사 | `node simulation/contracts/audit.mjs --require-panel` | 통과; dryRunReady=true, 실제 캡처 10개 pending·screenReviewReady=false |
| IPA 사전 검사 테스트 | Python 3.12.14: `python -m unittest discover -s simulation/cloud -p "test_*.py" -v` | 테스트 1개 및 내부 입력 변형 통과; 합성 IPA만 사용 |

IPA 테스트의 최초 실행은 샌드박스 기본 임시 폴더의 쓰기 권한 때문에 실패했다. 제품·테스트 코드는 바꾸지 않고 Python tempfile의 임시 경로를 워크트리 `.validation-tools/skill-check-temp` 안으로 지정한 프로세스에서 같은 테스트를 재실행해 통과했다. 런타임이 제공된 경로와 파일 쓰기 환경을 확인하도록 한 스킬 절차와 일치한다.

## 독립 평가 사례

1. 배포 준비만 요청, main에는 추가 미검증 커밋, 과거 iPad CI 성공: 과거 성공을 재사용하지 않고 대상 트리/검증을 대조하며 push·배포하지 않는다.
2. 계정 변경 검사만 요청, 검사 실패: 재현·분류·근거/수정 제안 보고까지 진행하고 제품·테스트·Git 변경을 추가하지 않는다.
3. 웹 60세션 통과 뒤 실제 iPad 흐름 질문: 실제 기기는 미확인으로 남기고 과제/증거 확보 절차를 안내한다.
4. 문서 작업 완료, 원본 main에 타 채팅 추적 미커밋 변경: 본인 문서는 커밋하되 통합은 차단·보존하고 완료 단계와 남은 단계를 보고한다. 소스 타 소유자의 미추적 파일 차단도 보존한다.
5. 승인된 서버 migration 적용 요청, 현재 적용 상태 미확인: 재승인을 요구하지 않고 먼저 읽기 전용 상태/전제 확인 후 승인된 정확한 변경만 적용한다. 접근이 없으면 미확인을 보고하고 실행하지 않는다.

평가자는 예상 결론을 제공받지 않은 별도 에이전트였으며 저장소 읽기와 가정 사례 대입만 수행했다. 수정 후 영향을 받는 사례를 다시 평가해 지적 사항 해결을 확인했다. 이는 실제 운영 배포·DB 적용·iPad 조작의 실행 검증이 아니다.

## 설치와 완료 확인

수정한 프로젝트 원본을 개인 Codex 설치본에 동기화하고 파일별 SHA-256을 대조한다. 커밋·로컬 통합 뒤 본인/원본 폴더 상태, 최종 커밋·ancestry, 설치본/통합본 일치를 최종 확인하며 커밋 ID와 통합 결과는 완료 응답에 제공한다.

이번 범위에서 구조·참조 오류와 발견한 지침 충돌을 수정했다. 모든 향후 입력에 오류가 없다는 보장은 아니며 실제 작업에서 새 사례가 확인되면 해당 스킬만 보완한다. 전체 iOS 빌드·XCTest·실기기·원격 push/Actions·배포·운영 DB·유료 실행·Claude 설치/호출은 수행하지 않았다.
