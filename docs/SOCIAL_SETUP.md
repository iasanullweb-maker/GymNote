# 친구·그룹 경쟁 설정

공통 최고 기록 종목(푸쉬업·풀업·신디 등)의 최고기록을 친구·그룹원과 겨룬다. 추가 서버 없이 기존 Supabase를 사용한다.

## 현재 프로젝트의 적용 상태 (2026-10-09)

최신 앱은 **0.1.91/build 91**로 배포됐다([빌드](https://github.com/iasanullweb-maker/GymNote/actions/runs/37940596587)). 친구·기록·실행 탭 코드 통합과 macOS 앱/위젯 빌드·iPad XCTest·격리 PostgreSQL 17 검사를 완료했다. **운영 서버의 002 정수 기록 적용 여부는 미확인, 003 친구 탈퇴는 이번 작업에서 미적용**이다. Supabase 로그인 연결이 없어 서버 조회/적용을 수행하지 못했다. 앱 배포와 운영 서버 준비 완료를 구분한다. 실기기 확인 항목은 [점검표](RELEASE_DEVICE_CHECKLIST.md)를 따른다.

다음 내용은 기존 001 적용 이력이다.

원격 인계 커밋 `33f5569`에 `202610090001_social.sql` 실행·권한 확인 완료 기록이 있다. 앱은 `4497785`의 통합 검증 후 0.1.83으로 배포됐으며 이번 문서 대조에서도 Actions·릴리스·AltStore 소스를 확인했다. 기존 프로젝트에 마이그레이션을 다시 실행하지 않는다. 남은 일은 두 계정의 친구 요청·그룹 초대·순위·공개 끄기 실기기 확인이다. 이번 문서 대조에서 운영 DB를 직접 다시 조회한 것은 아니다.

## 새 프로젝트 서버 적용 (한 번)

1. `202610080001_accounts.sql`, `202610080002_record_catalog.sql`이 적용된 상태인지 서버 테이블·RPC로 확인한다. 앱에는 캐시/번들 공통 목록도 있으므로 **공통 종목이 보이는 것만으로 적용을 판단하지 않는다**.
2. Supabase → **SQL Editor** → New query에 `supabase/migrations/202610090001_social.sql` 전체를 붙여 넣고 **Run**.
   - 편집기에 기존 내용이 남아 있으면 먼저 모두 지운다(이어 붙이면 이미 있는 표 오류로 중단된다).
   - 파일 전체가 하나의 트랜잭션이라, 중간에 실패하면 아무것도 바뀌지 않는다.
3. 앱 하단의 **친구** 탭 → 아래로 당겨 새로고침. '서버를 준비 중' 안내가 사라지고 닉네임 입력이 나오면 완료.

`scripts/test_social.sql`, `scripts/auth_test_schema.sql`은 테스트 전용이다. **실제 프로젝트에 실행하지 않는다.**

## 횟수·라운드 정수 제한 업데이트

기존 친구 기능 서버에는 `supabase/migrations/202610090002_integer_records.sql`을 추가 적용한다.
새 서버는 `202610090001_social.sql` 다음에 이 마이그레이션을 적용한다.
횟수(`회` 또는 빈 단위)와 라운드 값은 정수만 허용하며, 추가 횟수도 정수여야 한다.
무게·시간 등 측정 종목의 소수 기록은 유지한다. 기존의 소수 횟수·라운드 기록은 개인 백업에
그대로 남지만 경쟁 순위·자동 공개 후보에서 제외하며, 다음으로 좋은 유효 정수 기록을 공개한다.
서버 업데이트 전에도 새 앱은 잘못된 기록을 순위에서 제외하지만, API 직접 제출 차단과
구버전 앱의 순위 보호에는 서버 마이그레이션 적용이 필요하다.
`scripts/test_integer_records.sql`은 격리된 테스트 DB에서만 실행한다.

## 친구 기능 탈퇴 업데이트 (2026-10-09)

`supabase/migrations/202610090003_social_withdraw.sql`은 `202610090002_integer_records.sql` 다음에 적용하는 추가 마이그레이션이다. 로컬 격리 DB 및 GitHub CI의 PostgreSQL 17에서 검증했으며 **운영 서버에는 아직 적용하지 않았다**. 서버 적용 전에는 앱에서 탈퇴 준비 중 안내를 표시하고 기존 친구 기능은 유지한다. 이미 적용된 서버에서 003을 다시 실행하지 않는다. 기존 자료에 프로필 없는 관계/그룹/공개 기록이 있으면 외래 키 추가가 실패할 수 있으므로 적용 전 읽기 전용 확인을 하고 기존 자료를 임의 삭제하지 않는다.

친구 탭의 **친구 기능 탈퇴**는 확인 후 닉네임·친구 코드·친구 관계·그룹 참여·공개 기록을 제거한다. 그룹장은 남은 참여자에게 이전하고, 참여자가 없는 소유 그룹은 제거한다. 앱 계정·로그인 세션·개인 운동 기록·백업은 유지한다. 재가입하면 새 친구 코드로 시작하며 이전 관계는 복원하지 않는다. 프로필 외래 키는 탈퇴 뒤 늦게 도착한 친구 요청·공개 기록이 데이터를 되살리는 것을 차단한다.

`scripts/test_social_withdraw.sql`은 격리 테스트 DB 전용이다. 탈퇴·재가입·그룹장 이전·빈 그룹 정리·개인 백업 보존·익명/폐기 세션 차단·프로필 없는 기록/관계 삽입 차단을 검사한다. 운영 DB에는 실행하지 않는다.

## 화면과 기록 갱신

친구 가입 화면은 닉네임·공개 설정·가입 버튼을 구분하고 친구 추가 버튼은 친구 목록 첫 줄에 둔다. 기록 화면 순서는 **운동 일지 → 친구 → 최고 기록**이다. 최고 기록과 전체 기록 화면은 조회용이며 추가/수정/삭제 버튼을 제공하지 않는다. 갱신은 실행 탭 또는 지난 운동 기록에서 수행한다. 실행 탭의 입력 경로는 별도 Claude 담당 작업과 함께 통합 검증한다.

## 기능별 동작

- **시작:** 닉네임(1~20자)을 정하면 8자리 친구 코드가 생긴다. 닉네임을 정하기 전에는 아무 기록도 공개되지 않는다.
- **친구:** 친구 코드로 요청 → 상대가 수락하면 친구. 서로 요청하면 바로 친구가 된다. 친구 끊기·보낸 요청 취소 가능.
- **그룹:** 그룹을 만들고 내 친구를 초대 → 초대받은 사람이 참여하면 그룹원. 그룹원끼리는 친구가 아니어도 그룹 순위에서 기록이 보인다. 그룹장이 나가면 가장 먼저 들어온 그룹원이 그룹장이 되고, 아무도 없으면 그룹이 사라진다.
- **순위:** '내 친구 전체'(나와 친구) 또는 각 그룹. 종목 규칙(높을수록/낮을수록, 라운드형은 라운드×라운드당 횟수 + 추가 횟수)으로 정렬하고 같은 점수는 같은 순위.
- **자동 공개:** 공개를 켠 계정은 기록 탭의 공통 종목 최고기록(횟수 종목은 직접 기록과 운동 일지 중 높은 한 세트, 라운드형은 직접 기록)이 바뀌면 몇 초 뒤 자동으로 올라간다. 앱을 다시 열 때도 확인한다. 마지막으로 올린 내용과 같으면 보내지 않는다.
- **공개 끄기:** 설정 즉시 서버에 올린 내 기록을 지운다. 친구 기록은 계속 볼 수 있다.
- **계정 삭제:** 닉네임·친구 관계·그룹 가입·공개 기록이 모두 함께 삭제된다. 내가 그룹장인 그룹은 삭제된다.

## 보안·개인정보

- 앱은 표에 직접 접근할 수 없고 `social_*` 함수만 호출한다(공개 키로는 익명 호출 불가).
- 모든 함수는 활성 세션(로그아웃으로 폐기된 세션 거부)과 토큰의 사용자 ID로 호출자를 정한다. 요청 본문의 사용자 ID로 다른 사람의 데이터를 바꿀 수 없다.
- 기록은 나·친구·같은 그룹원에게만 보인다. 그룹 순위는 그룹에 참여한 사람만 볼 수 있다(초대만 받은 상태로는 불가).
- 보이는 정보는 닉네임과 공통 종목 기록뿐이다. 이메일·로그인 방법은 노출하지 않는다. 친구 코드는 내 화면에만 보인다.
- 공개 기록은 서버가 종목(사용 중인 공통 종목만)·값 범위·라운드 추가 횟수를 확인하지만, **실제로 그만큼 했는지는 검증할 수 없는 자기 기록**이다. 친구끼리의 동기 부여용이다.
- 제한: 보낸 대기 요청 50개, 가입 그룹 20개, 그룹 인원 50명.
